# Review Guidance

- Reviews are adversarial research critiques of ideas, questions, experiment plans, claims, decisions, or paper drafts.
- Review notes should identify the main strengths and weaknesses, especially unclear contribution, weak novelty, missing baseline, invalid metric, confound, unsupported claim, scope mismatch, or likely reviewer rejection. Assess whether the question and evaluation criteria address the intended scientific objective, especially when repeated refinements yield little progress.
- Reviews are not approval gates or planning sessions; they pressure-test the work so its risks are explicit.
- Each review should end with a concise verdict: most serious objection and suggested follow-up if any. Preserve unresolved disagreements that affect validity or direction, and state what evidence could resolve them rather than forcing agreement.
- Name review files `YYYY-MM-DD-short-title.md` using the date the review is recorded.
- Track review files from the category dashboard as `[review](YYYY-MM-DD-review-title.md): Open`, then replace `Open` with the verdict or linked follow-up.
